# ТЗ. Фильтр торговых дат в WF Grid

Редакция 2 от 21.11.2026. Статус — готово к реализации. Точка запуска — корневой `run.py`, конфигурация — `config.yaml`, движок — пакет из `donor`. Требования распространяются на train, OOS, последовательный запуск, workers и резервный последовательный запуск WF Grid. Самостоятельный TESTER в эту поставку не входит.

## 1. Какой результат должен получить пользователь

Пользователь задаёт множество дат. Стратегия работает на исходной шкале котировок, открывает сделки только на допустимых барах и закрывает остаток позиции по close последнего разрешённого бара перед запрещённой датой. Доходность сделки заканчивается на этом исполнении. Показатели риска учитывают время простоя.

**Назначение результата — ретроспективное исследование сетки параметров.** Граница дня определяется по фактически записанным следующим барам. Список дат считается заданным для всего опыта; два CSV не устанавливают момент, когда этот список и расписание были известны участнику рынка. Рейтинг сохраняет действующий порядок WF Grid: метрики каждой точки считаются в train и OOS, итоговый ранг строится по агрегированным OOS-результатам. В метаданных активного запуска указать «Ретроспективный отбор дат по наблюдаемым барам; итоговый рейтинг по OOS». Независимая оценка выбранного до OOS победителя и моделирование биржевой заявки на закрытие сессии — отдельные задачи. Цена close здесь является условием исторического исполнения.

## 2. Конфигурация и входные данные

В существующую секцию добавить дочерний блок. Старые конфигурации продолжают загружаться.

```yaml
trade_filter:
  enabled: true           # существующий общий выключатель
  date_filter:
    enabled: false
    file_path: "data 1.csv"
```

1. Активность равна логическому И родительского и дочернего `enabled`. Отсутствующий блок или дочерний переключатель означает false. Отсутствующий `file_path` получает значение `data 1.csv`. Явный блок должен быть отображением, `enabled` — YAML boolean, явно заданный путь — непустой строкой. Неизвестные ключи отклоняются штатной строгой схемой. В неактивном режиме нет обращения к файлу, включая проверку существования. Добавленный выключенный блок сам по себе не делает законной ранее недопустимую конфигурацию.
2. Допустить самостоятельный режим «только даты» при включённом родителе и выключенных остальных фильтрах, а также даты с любым уже допустимым сочетанием фильтров. Сохранить существующие defaults других блоков и ограничения совместимости. Абсолютный путь использовать как задан; относительный путь списка разрешать от каталога корневого `run.py`, независимо от cwd и расположения YAML.
3. Источник списка — CSV UTF-8 с необязательным BOM, разделитель `;`, стандартное CSV-кавычкование; одноколоночный файл допустим. В заголовке нужна ровно одна колонка с точным именем `<DATE>`. Пропускать полностью пустые физические строки. Каждая запись данных должна содержать поле даты. После удаления внешних пробелов и табуляции значение должно состоять ровно из восьми ASCII-цифр и обозначать существующую григорианскую дату YYYYMMDD. Пустое значение в записи, включая `""`, ошибочно. Время, тикер, цены и остальные поля не валидировать как рыночные данные. Проверить весь файл, включая дубликаты и даты вне истории.
4. В основной истории использовать локальную календарную дату бара в исходной временной шкале FINAM. Метка 00:00 принадлежит новой дате. Уточнение относится к календарной дате строки, включая вечерние торги; биржевой перенос метки сессии через полночь не применяется. Основной CSV проходит штатную загрузку и валидацию. Все маски выравниваются с окончательным хронологическим индексом загруженной истории.
5. Построить множество уникальных дат S. При непустом пересечении с основной историей разрешены лишние даты; на входы они не влияют. Ошибки чтения, кодировки, синтаксиса CSV, заголовка, значения, пустой список и нулевое пересечение завершают весь запуск до расчёта сетки и старта workers с ненулевым кодом CLI. Сообщить разрешённый путь, причину, для ошибочной записи — номер строки и значение. При нулевом пересечении указать количества уникальных дат обеих сторон. При ошибке не создавать отчёт успешного запуска.

## 3. Маски и порядок событий

Для N баров полной истории в порядке исполнения определить три булевых признака, индексация от нуля.

```text
A[i] = date[i] ∈ S
B[i] = A[i] AND i+1 < N AND NOT A[i+1]
E[i] = A[i] AND NOT B[i]
```

Проверка `i+1<N` предшествует обращению к следующему элементу. B обозначает бар обязательного закрытия, E разрешает открывающую часть заявки. Признаки вычисляются один раз на полной истории, затем нарезаются вместе с барами. Перерыв между соседними записями любой длины сам по себе не образует B. На конце файла B=false. На конце train/OOS B может быть true. Единственный бар разрешённого дня перед запрещённым имеет B=true.

| Фаза бара i | Обязательное действие |
|---|---|
| До open | Взять заявку, которую штатная стратегия могла подготовить по данным до i. У фильтров времени, объёма и подтверждения остаются их собственные часы принятия решения. Дата проверяется для исполнения на i. |
| Open, E=true | Исполнить штатно разрешённую заявку по Oᵢ. Сохраняются режимы long, short и revers/both, приоритеты выходов и подтверждений. |
| Open, B=true | Блокировать любой вход и увеличение экспозиции. Если на open уже назначен законный выход, исполнить его по Oᵢ. Подтверждённый разворот разложить на закрытие старой стороны и открытие новой: исполнить только закрытие. При отсутствии исполнимого выхода сохранить прежнюю позицию до close. |
| Close, B=true | Если позиция ещё открыта, закрыть её по Cᵢ с причиной `date_filter_close`. Если позиция уже нулевая, не создавать операцию. Решение штатной стратегии на этом close для будущего open не отменяет состоявшееся закрытие. |
| Бар A=false | Позиция нулевая во всех фазах. Цены и объёмы обновляют индикаторы и обычные наблюдения за рынком. Ни дохода от цены, ни комиссий этого бара нет. |

**Повторный вход.** Смена допуска по дате сама не создаёт торговый сигнал. На первом подходящем open исполнима только штатная попытка на этот open. Например, при постоянной целевой позиции базовая стратегия из flat может войти, а режим, которому требуется новый edge или открытие временного окна, ждёт своего события. Сигнал на последнем запрещённом close для следующего разрешённого open допустим. Заявка, отклонённая на своём open, погашается; очередь пропущенных входов не накапливается.

**Состояние стратегии.** Применять запрет на стадии исполнения, до фиксации перехода владельцем позиции. Отклонённый вход не открывает виртуальную сделку и не расходует лимит исполненных входов. Выход закрывает реальную сделку, очищает привязанные к ней ожидающий разворот, подтверждение, стоп и заявки старой стороны. Независимые от владения позицией индикаторы, наблюдаемые рыночные циклы и их штатные сбросы продолжают работу. Сигнал штатного выхода на open сохраняет свою причину. Причина `date_filter_close` принадлежит только фактическому исполнению на close. Один выход — одна причина и одна комиссия, в том числе при совпадении с решением time reset, daily reset или FSM на том же баре.

## 4. Цена, комиссия и доходность

Источник для журнала и баровых результатов — одни и те же фактические исполнения с идентификатором сделки, глобальным индексом бара, фазой, стороной, ценой и причиной. Выбор внутренней структуры остаётся разработчику. Позиции на open и после close могут различаться. Маски поверх готового журнала или одного массива конечных позиций недостаточно.

Пусть q ∈ {−1,0,+1} — позиция после операций на open, c — доля комиссии за сторону. На обычном интервале ценовой вклад равен `q × (Oᵢ₊₁/Oᵢ − 1)`. Для остатка на B он равен `q × (Cᵢ/Oᵢ − 1)`; вклад от Cᵢ до следующего open равен нулю. На open, где позиция закрылась полностью, q=0 и последующего внутрибара у старой сделки нет. Комиссия каждой единичной стороны равна c; полный разворот стоит 2c. Штатная техническая оценка позиции в конце среза не создаёт комиссию за неисполненный выход.

Для закрытой сделки с направлением s, ценой входа P и исполнения выхода X валовой процент равен `100 × s × (X/P − 1)`. Из него вычитается `100 × c` за каждую фактически исполненную сторону этой сделки. Соблюдать штатное округление полей журнала до шести десятичных знаков; баровые вычисления выполнять без промежуточного округления. `sum_pnl_pct` — сумма net по строкам журнала. Equity рассчитывается сложным начислением по доходностям периодов, с действующим защитным минимумом движка. Комиссии сверять по сторонам и принадлежности сделке, а не через равенство этих двух показателей.

### Привязка к периодам окна

Для активного режима задать следующий эталон проекции на штатные Nw−1 доходностей окна из Nw баров. Он сохраняет существующую сетку периодов для Sharpe, Sortino, CAGR и границ прогрева.

* Базовый слот j соответствует промежутку open j → open j+1. Включить его ценовой вклад и комиссию принадлежащих выборке операций на правом open. При B на j выходную комиссию на close j отнести в этот же слот. Комиссию входа в сделку выборки на самом первом open учесть в первом слоте, так как предшествующего слота в окне нет. Все комиссии — вычитания из доходности соответствующего слота.
* Если B выпал на последний бар окна и позиция дожила до его close, сначала рассчитать последний штатный слот до последнего open с доходностью r. Затем применить терминальный множитель `1 + u`, где `u = q × (C_last/O_last − 1) − c`. Итоговая доходность последнего слота равна `(1+r) × (1+u) − 1`. Выход отражается отдельным исполнением на последнем close. Новая строка котировок и дополнительная годовая доля не создаются. При обычном выходе на последнем open его комиссия уже в r, u=0. Просадка для отчётности измеряется по той же штатной сетке equity, включая итоговую оценку на последнем close.
* При нуле периодов журнал отражает принадлежащие окну фактические исполнения; метрики, требующие периода, получают штатное невалидное значение. Порог достаточности баров применяется прежде статуса отсутствия сделок. Полноценное окно с нулём сделок получает `no_trades`. Для случая меньше двух баров нельзя искусственно создавать период или заимствовать следующую цену.

## 5. Walk-forward, выборки и отчёт

1. Сохранить полную основную историю для границ train/test/step и годовой частоты. Train инициализировать на штатном train-срезе, OOS — с действующим prepend. В каждом из них подать индикаторам все бары, включая запрещённые. Сохраняются штатные правила прогрева баровых метрик и выборки trade-метрик. В сочетании с ZigZag существующие статистики по всей истории остаются частью ретроспективного исследования; добавление списка дат не придаёт им причинности.
2. Для OOS отбирать сделки по исполнению входа внутри окна. Сделка с входом в prepend исключается целиком, включая её ценовой вклад и комиссию при выходе на первом или последующем OOS-close. При развороте на OOS-open старая и новая сторона атрибутируются раздельно. Вклад новой сделки начинается с её фактического входа, включая входную комиссию. Прогретое состояние стратегии и возможность законного сигнала с последнего prepend-бара сохраняются. Баровую экономику OOS собирать из принадлежащих выборке вкладов, затем пересчитать equity от 1 и метрики.
3. Если на последнем баре среза B=false и сделка остаётся открытой, сохранить штатную оценку по последнему open, учёт строки в статистике и правила `pending_open_trade_at_end`. При B=true реальный close заменяет техническую оценку этой сделки. Использовать только метку следующей даты при построении B. За пределами окна не брать цены или сигналы для PnL.
4. Для M строк действующей trade-выборки использовать `win_rate=100×count(net>0)/M`, `avg_trade=Σnet/M`, `PF=Σ(net>0)/|Σ(net<0)|`, где в суммах PF складываются значения net соответствующего знака. Нулевой net входит в M. При M=0 принять num_trades=0, sum=0, win_rate=0, avg и PF невалидны. При положительной прибыли без убытков применяется штатный верхний предел PF, при всех нулевых net PF невалиден. Принудительное закрытие формирует одну строку. Сохраняются пороги минимального числа сделок.
5. Баровые метрики включают все штатные периоды после применимого прогрева, в том числе нулевые интервалы простоя. `periods_per_year` определяется по всей истории. Статус и gates имеют прежний приоритет; `ok_ratio=N_ok/N_всех_шагов`. Агрегаты считаются по прежним валидным значениям среди OK-шагов. Пустой шаг остаётся в итоговом числе шагов. В WF Grid по-прежнему отклонять `early_exit_enabled: true` при проверке конфигурации.
6. В выгрузке сделок активного режима указывать фактические цену, индекс, исходную временную метку бара, фазу выхода `open` или `close` и причину. Для технической оценки предусмотреть отдельную метку фазы `mark_open`. Поле времени идентифицирует бар; точную биржевую секунду закрытия не выводить из времени начала бара. `bars_held` сохраняет принятую разность индексов; фаза различает выходы на одном индексе. Обязательные поля работают и при выключенной подробной побаровой диагностике.
7. Один экземпляр календарных данных на запуск: загрузить и проверить до workers, нарезать по тем же абсолютным смещениям, что и OHLC. Пересчёт в fallback обязан использовать те же признаки; ошибка их доставки завершает расчёт с диагностикой. В метаданных активного запуска сохранить путь, число дат списка, совпадений, разрешённых баров, границ B и правило рейтинга из §1. Идентификатор состава списка — SHA-256 от отсортированных уникальных YYYYMMDD, соединённых LF без завершающего LF, в UTF-8. Число границ B и число исполненных выходов учитывать раздельно.

## 6. Совместимость

При выключенном фильтре старые сделки, комиссии, позиции, метрики, статусы и рейтинг должны воспроизводиться на прежнем пути, в том числе при отсутствии файла списка. При активном фильтре, покрывающем все даты, B везде false: требуется паритет сигналов, исполнений, цен и trade-PnL с исходной стратегией. Для баровой экономики OOS действует уточнённое правило принадлежности комиссий и нормировки equity из §§4–5. Расхождение с историческим результатом допустимо только при воспроизводимом различии из-за этой коррекции и производных от неё метрик, gates и ранга. В контрольном окне без такой разницы требуется численный паритет. Это явное различие между режимами разрешает противоречие требований к обратной совместимости и точному учёту комиссии первого OOS-open.
